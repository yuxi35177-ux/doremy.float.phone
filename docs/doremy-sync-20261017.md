## 移植与冲突处理

1. 本地模型 API：移植 LocalApiBridge、网页端传输、API 设置/模型获取、嵌入请求接入、WebKit 依赖和仅 loopback 明文网络配置；带上后续精确域名配置修正。保持在线 API 分支。原生桥只向受信站点主框架开放，限定本机路径、请求方法和头；流式支持背压、取消和错误传播。
2. 面具：移植完整 KV、IndexedDB、记忆、聊天、剧情、媒体、工具与备份边界；当前面具首次取得旧库所有权，不搬移、不清空旧档。切换等待写入、提交路由后重载，旧页面的存储作用域保持固定；中止聊天生成和后续调度，非当前会话通知回复延迟处理。API、角色模板、主题等可复用资源保持共用。
3. 目标 float-enhancer 的 Storage.prototype 全局内存镜像存在延迟落盘、吞写入异常、枚举与缓存不一致的问题。移除这层重写，保留浏览器同步存储语义。额外修复晚加载迁移提前删除旧副本、启动迁移失败后重试误以为缓存值已落盘的两个数据保全问题。
4. 本地通知：移植独立开关、测试、系统设置入口、后台当前聊天通知策略、短窗口会话去重；保留 PushService 与云推送架构，仅补充通知身份字段的透传；本地通知有独立设置。真实云端/原生同时到达时的通知体验仍待实机验证。
5. 返回：采用明确返回控件、可见性命中检测、弹窗/聊天菜单优先级的网页统一入口；整合目标左右两侧向内滑动，增加输入/横向滚动排除、触摸取消和重复触发抑制。删除普通点击不断 pushState 和第二套 popstate 处理，避免双重导航。
6. 性能：桌面滑动逐帧批量绘制、拖动宽度复用、背景采样并发缓存/有界淘汰、大型应用按需加载。删除网页和原生注入里的全局禁模糊与全局 transform/touch-action；仅桌面滑动期间临时降低指定玻璃组件开销。
